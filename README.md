# 现在做什么

纯 HTML、CSS、JavaScript 的碎片时间任务助手。选择时间和环境，立即得到适合当前状态的小任务；数据只保存在浏览器 `localStorage`。

直接双击 `index.html` 即可运行，无需 Node.js、npm 或服务器。

## GitHub Pages

1. 在 GitHub 创建仓库并上传全部文件。
2. 打开 **Settings → Pages**，选择 **Deploy from a branch**。
3. 选择主分支和 `/ (root)`，点击 **Save**。
4. 访问 `https://你的用户名.github.io/仓库名/`。

这是从自己长期想做的活动中，根据当前时间和环境选出一项、立刻开始的工具。功能包括随机推荐、任务执行与完成记录、今日统计、任务筛选、自定义任务、JSON 导入导出、深色模式。结束的是本次执行，活动本身继续保留。

用户数据仅保存在当前浏览器的本地存储中；建议定期导出 JSON 备份。清除浏览器数据、更换浏览器或设备后，不会自动同步恢复。

个人备份、日记及存储导出应保存在仓库外；如需放在本地项目内，请使用 `private-data/`、`personal-backups/` 或 `personal-diaries/`。这些目录及应用生成的备份文件名已加入 `.gitignore`，正式文档、配置及静态图片不会被统一排除。忽略规则不能保护已经跟踪的文件，也不会清除旧提交中的内容；每次发布前仍需检查暂存内容及提交历史。不要将真实用户数据用作测试夹具。

本地提交前的隐私审查、回归结果及未验证边界见 [发布前检查记录](docs/release-privacy-validation.md)。

## 数据保护

- 首次使用且主数据不存在或为空字符串时初始化空任务库，不写入示例任务或目标。已经保存的空任务数组表示用户保留空库，刷新、重启或新版迁移均不会补入默认内容。已有数据无法读取、解析或迁移时，停止保存并显示保护界面，不自动重置。能够读取的原始主数据及计时内容可以分别导出为文本留存。
- 保存失败会持续提示，主数据恢复到操作前的内存快照，任务编辑框保留输入以便重试。完成记录保存失败不会清除活动计时；计时清理失败会保留已保存的记录，并在重新加载后重试清理。
- 支持现有 v2 备份及旧版备份。导入先校验并确认替换目标、任务、记录、偏好、主题和备份中的其他主数据；保存成功后同步界面。单独存储的活动计时不随 JSON 备份导入或导出。
- 旧版迁移保留原有目标、任务、历史记录和其他字段，仅补充缺省设置、缺失记录 ID；不补入默认任务或目标，不补造旧记录的开始或结束时间。已有主数据的迁移不在启动时自动回写，重复迁移不会重复创建记录。存储键仍为 `whatToDoData` 和 `activeTimer`，版本仍为 v2。
- 目标导航、管理页面、筛选和任务关联输入已移除。旧 `goals`、`goalId`、记录中的目标快照及可选分类字段仍兼容保存在数据和 JSON 备份中；编辑旧任务保留这些字段，不要求关联有效目标。不含 `goals` 的合法备份在内存中补为空数组，旧目标不会转成任务。

## 推荐条件与状态

首次打开或刷新后，时间和环境均未选择，随机推荐不可用；选齐后才计算推荐。该确认状态只属于当前页面会话，不改变原偏好数据格式。页面内导航保留确认状态，刷新重新选择；导入或主题同步不会替尚未选齐的用户确认条件。

推荐要求任务预计分钟数小于或等于可用分钟数，环境精确匹配，同时满足电脑可用性和启用状态；不以目标或分类作为条件。听课环境继续排除需要电脑的任务。主动推荐或“换一个”在存在其他合法候选时先排除上一项，再优先避开近 7 天练习过的任务；回退仍不放宽硬条件。只有一项符合条件时，会保留该项并明确提示。

更改时间、环境或电脑偏好且保存成功后，立即校验并保留仍有效的推荐；旧推荐无效时重新选择，无候选时立即显示空状态。保存失败时保留原偏好和有效推荐。推荐的开始按钮会重新核查任务和条件，手动从任务库开始任务仍保持原行为。推荐不会修改任务预计时长、活动计时或完成记录。

开始页将“随机推荐”和“自己选择任务”并列展示，后者直接打开原任务库，沿用任务库筛选和启动行为，无需先选推荐条件。结果紧跟选择区，开始任务为主操作，任务说明可展开查看；小窗口中需要时将开始按钮滚入可视区域，不使用固定悬挂按钮。最新布局及刷新未选规则的验证见 [开始页快速启动验证](docs/start-page-validation.md)。

验证记录见 [推荐筛选与状态验证](docs/recommendation-validation.md)。可运行：

```powershell

node tests/browser-data-safety.cjs tests/browser-recommendation.cjs
```

## 可重复任务与学习记录

任务库记录可以反复执行的学习活动。每次完成计时新增一条执行记录，不把任务永久标记为已完成；任务库已移除基于历史记录的“已完成”筛选。旧数据中的所有记录和额外字段继续保留，没有重置或删除操作。

“今天”按浏览器本地日期展示每次执行及有效用时，不把完成记录数量当成永久完成的活动数量。旧目标元数据保留在数据备份中，不再提供独立目标页面；没有目标的任务可以直接添加、编辑、推荐和执行。

本轮反馈定位、兼容方案和只读证据要求见 [推荐反馈与可重复任务验收记录](docs/recommendation-feedback-validation.md)。双击本地文件入口的隔离测试可运行：

```powershell
node --test tests/repeatable-tasks.test.cjs tests/recommendation.test.cjs tests/data-safety.test.cjs
node tests/browser-data-safety.cjs tests/browser-repeatable-tasks.cjs --file
```

## 空任务库、旧数据和不同入口

空库显示“添加一件你想经常做的事，有空时让我帮你选。”及添加按钮。名称输入框中的例子只是 placeholder，不会自动保存；新任务默认 10 分钟、安静环境、不需要电脑，可按实际情况修改。

旧默认任务可能已被用户修改，不能仅凭名称或 ID 自动识别和删除。安全清理方式：

1. 在当前实际使用的浏览器及地址打开应用，先打开顶部“数据管理”并点击“备份我的数据”，保留 JSON 备份。
2. 在任务库将时间、环境筛选切回“全部”，取消电脑筛选，逐项核对后点击“删除”并确认。删除任务不会删除执行记录或旧目标数据。本轮没有新增批量清理。
3. 删除全部任务后刷新，任务库应仍为空。需要恢复时，先导出当前数据，再导入原备份并确认替换；导入不是合并。

浏览器 `localStorage` 按 origin（协议、主机、端口）隔离，HTTP/HTTPS、不同域名或端口不会自动共用数据；同一 origin 的不同路径一般共用。`file://` 的存储规则由浏览器决定，不应依赖其跨文件共享。隔离 Chrome 测试确认，本地文件入口和本地 HTTP 入口各自保存不同数据。切换到新入口前先在旧入口导出 JSON，再在新入口导入；活动计时单独存储，不在 JSON 备份中，应先结束计时。

仓库没有 Service Worker 注册或缓存脚本，资源使用版本参数更新浏览器缓存。缓存可能使旧代码继续运行，但清理浏览器数据会丢失本地内容，不能作为数据处理方法。无法访问原入口的数据时先检查浏览器配置、准确网址和文件路径，不要把新入口的空库当作旧数据已被删除。不要用旧版本应用打开空库后继续保存：旧代码仍可能重新补入默认内容。

本轮结果见 [空白初始化与活动兼容验证](docs/personal-activities-validation.md)。相关检查：

```powershell
node --test tests/data-safety.test.cjs tests/recommendation.test.cjs tests/repeatable-tasks.test.cjs tests/personal-activities.test.cjs
node tests/browser-data-safety.cjs tests/browser-personal-activities.cjs --file
```

## 网页内悬浮计时器

开始任务后显示完整计时页面；点击导航切换到今天、任务库或开始页时，计时器缩为右下角悬浮窗。按住非按钮区域可以拖动，轻点或用键盘 Enter/空格可返回完整计时页面。暂停/继续和结束按钮独立操作，不触发返回；结束弹窗可选择完成、放弃或取消。完成只记录本次执行，活动继续保留。

完整视图与悬浮窗共用原有 `activeTimer` 和单个刷新循环，切换或拖动不写入计时数据。悬浮位置只在当前页面会话保留；刷新后沿用已有计时恢复规则并显示完整视图，下次悬浮默认回到右下角。旧版已到时的计时可通过“继续”复用原追加时间操作。系统休眠计时语义仍待确认；原自动追加的整分钟取整规则保持不变。

本功能只在网页内部显示，不会在其他软件上方置顶。实现与实际验证见 [悬浮计时器验证](docs/floating-timer-validation.md)。

```powershell
node --test tests/floating-timer.test.cjs
node tests/browser-data-safety.cjs tests/browser-floating-timer.cjs --file
node tests/browser-data-safety.cjs tests/browser-floating-timer.cjs
```
