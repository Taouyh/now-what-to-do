# 计时中断与恢复验收

日期：2026-10-27。已按确认的产品图修改正式应用。本文记录 1.3.0 发布前验证；下载见 GitHub Releases。

## 用户行为

- 本轮到点后停在 00:00，等待时间不计入有效用时，也不自动追加。点击「继续」才按原有规则追加一段；点击「结束并记录」保存到实际到点的时间边界。
- 正常关闭网页或 Windows 窗口后，保存进度；重新打开显示待恢复卡片，等待「继续本次」或「结束并记录」。离开期间不算有效用时或暂停时间。
- 暂停或等待已满一小时，按长暂停处理；关闭后离开满一小时也适用。「接着做」先保存旧的一段，再为同一活动开启新计时；上一次的时间边界不延伸到今天。
- 上一版没有可靠检查点的运行中计时，要求确认实际用时，不从离开时长猜测。用户也可通过「不记录这次」明确放弃，取消确认则保留原计时。已保存的完成记录不会自动修改。
- 三语、深色、窄屏、触屏、键盘和悬浮入口保持可用。

## 保存与时间边界

活动计时新增可选 `timerVersion: 2`、`checkpointAt`、`stoppedAt`、`timeUpAt` 和恢复状态字段。继续沿用原 `activeTimer` 存储项；主数据和备份仍为 v2，不更换数据目录。

- 正常运行约每 5 秒保存一次已投入时间，正常退出另存一次。异常终止只能恢复最近成功的检查点，可能少计约一个保存间隔。
- 到点固定 `timeUpAt`，不会把等待确认的时间算入记录。长暂停记录截止于上次可信边界，当前这一夜不会加入暂停累计。
- 可见页面超过 2 分钟没有检查点，保守进入中断恢复。已知处于后台时允许本轮按时长上限继续，超过一小时没有检查点则恢复最近进度。网页无法可靠判断离开屏幕后是否仍在活动，因此不以“没有点击工具”判定用户停止。
- Windows 等待关闭回调保存，最长等待 1.5 秒；休眠通知触发冻结。安卓在后台、停止、恢复阶段通知网页，检测屏幕关闭时触发中断冻结；进程突然终止由定期检查点兜底。
- 旧计时的原始快照保留在待恢复计时中；用户确认并记录后保存在完成记录的 `timerRecoveryOriginal` 中。无可靠进度时不自动套用原计划时长。

## 写入失败

保存旧段记录成功后才替换为新计时；任一步失败均保留可重试状态。完成 ID 防止重试产生重复记录。主记录成功但计时清理失败时，重新打开会去重清理，不会自动再记一次或启动任务。
