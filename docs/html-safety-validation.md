# HTML 渲染安全审计与验证

日期：2026-10-19。修复前基线：`8808081`。本轮仅修复用户文本被 HTML 解析及 ID 被拼入内联事件的问题，不修改推荐算法、计时规则、统计口径、存储格式和导入业务。

## 只读审计结果

检查了产品文件中的 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、HTML 模板字符串、属性、URL、样式、事件以及其他代码解析入口。基线存在以下 **6 个动态 HTML 输出风险点**，分布于 5 个渲染函数：

| 输出位置 | 用户可控来源 | 原输出上下文及风险 |
| --- | --- | --- |
| `random()` 推荐卡片 | 任务名称、描述，来自编辑表单、已存数据或 JSON 备份 | 拼入 HTML 文本，标签及事件属性可成为节点并执行。 |
| `tasks()` 任务卡片 | 任务名称、描述，关联目标名称、图标 | 拼入卡片 HTML，文本可被解析为标签及事件属性。 |
| `tasks()` 目标筛选选项 | 目标 ID、图标、名称 | ID 拼入 `option value="..."`，引号可逃出属性；标签内容也经 HTML 解析。 |
| `goals()` 目标卡片及按钮 | 目标名称、说明、图标、ID | 文本进入 HTML；ID 同时进入 HTML 属性中的 JavaScript 字符串，存在双重上下文，普通文本转义不足以保护。 |
| `today()` 完成记录 | 已保存的任务/目标名称快照；旧记录回退读取的当前名称 | 拼入历史记录 HTML，已导入或已保存的文本也可触发存储型注入。 |
| `newTask()` 任务编辑框目标选项 | 目标 ID、图标、名称 | 与筛选选项相同，存在属性及文本上下文风险。 |

基线另外存在固定界面模板和仅含固定枚举/计算数字的计时按钮模板。保护界面、存储提示、目标编辑框、电脑偏好控件的 HTML 为代码中的固定文本；错误详情和用户字段分别使用 `textContent` 或表单 `.value`。确认框、通知和计时任务内容已使用安全文本 API。

未发现产品文件使用 `outerHTML`、`document.write`、`DOMParser`、`createContextualFragment`、`eval` 或 `new Function`。下载链接来自本应用创建的 Blob URL，资源 URL 为固定值，没有将用户输入作为可导航 URL。进度条宽度由计数或数值计算产生，没有用户文本拼入 CSS。

测试驱动中的 Node VM、Chrome `Runtime.evaluate` 和受控测试载荷用于隔离验证，不由产品页面加载，也不读取真实用户配置。

## 修复方式与范围

- 增加 `textElement()`、`actionButton()`、`renderGoalOptions()` 三个小型辅助函数，使用 `createElement`、`textContent`、`.value`、`replaceChildren` 和函数事件处理器。
- 修改上述 5 个函数的输出部分。保留原有 DOM 层级、CSS 类、任务事件委托，以及候选选择、筛选、进度和历史时间计算表达式。
- 目标按钮通过闭包传递原始 ID，移除 HTML 内联 `onclick`。ID 不再进入 HTML 属性或 JavaScript 源码字符串；不根据用户 ID 构建 CSS 选择器。
- 任务按钮的 `data-task-action` 为固定枚举，`data-task-index` 为本次渲染数组索引。目标选项的原始 ID 只写入 `.value`。
- 计时按钮继续使用固定 HTML 骨架；暂停/继续及追加分钟文字改由 `textContent` 填入，避免留下动态 HTML 拼接。
- 增加一条文本样式，保留卡片名称、描述及计时/确认任务名称的换行和长文本折行；不更改颜色、布局或字体规则。原生下拉列表的排版仍遵循浏览器控件行为，选项文本和 ID 的完整字符串均保留。

修复后产品中保留 **5 处 `innerHTML`、1 处 `insertAdjacentHTML`，全部为固定界面字面值**。动态内容使用文本或 DOM 属性 API。没有标签黑名单、正则过滤器或自行实现的 HTML 清洗机制；应用当前不支持用户富文本。

## 数据兼容

没有增加数据字段、迁移版本或修改保存格式，不对已有文本做预转义、解码或清洗。包含 `<`、`>`、`&`、单双引号、`&amp;`、`&copy;` 和 HTML 标签的内容仍按原字符串存储，显示时作为普通文本。

读取、迁移、导入校验、保存及计时生命周期代码保持上一阶段实现。测试证明仅切换页面和渲染不会回写或覆盖已有主数据。新增、编辑、删除和确认导入仍按原流程保存用户明确提交的变更。

## 测试方法

复用原 Chrome 无头测试驱动，仅增加可选测试模块参数，继续使用新建临时配置和每场景独立的浏览器上下文。全程仅使用合成测试数据；不会打开用户日常 Chrome 配置。

注入载荷包括带本地不存在资源和 `onerror` 的图片、带 `onload` 的 SVG、HTML 标签、包含引号的 ID，以及可逃出原内联 JavaScript 字符串的 ID。脚本载荷只增加当前测试页面的无害计数器，没有读取 Cookie、访问远程站点或传出数据。

测试同时检查计数器为 0、未生成载荷标记节点、`textContent` 与原始输入完全相等、表单和下拉列表 ID 正确、存储原文不被编码修改。测试通过真实表单和按钮事件验证交互，没有通过禁用页面脚本或 CSP 隐藏漏洞。

```powershell
node --check tests/browser-data-safety.cjs
node --check tests/browser-html-safety.cjs
node --test tests/data-safety.test.cjs

```

## 实际边界

本轮审计覆盖当前产品源码中发现的 HTML 输出路径，未留下已知的用户文本动态 HTML 解析点。保留的固定模板后续仍需避免混入用户数据；本轮没有引入富文本机制。

这不是对所有未来代码或所有浏览器的 XSS 保证。未执行全面载荷模糊测试、多浏览器或全站人工视觉验收；这些测试也不代表其他未覆盖功能已经验收。上一阶段说明的多标签页并发覆盖等存储限制不属于本轮修复范围。
