# 续做反馈的消失与连续完成

本文的无超时规则只适用于正常结束后的续做反馈。用户放弃计时时不显示续做反馈，而显示可自动消失的 [30 秒放弃提醒](DISCARD-NOTICE.md)。

2026-11-02。用户要求保存或取消后反馈自动消失，仅未操作时保留；同时需要解决连续完成任务后的叠加问题。本轮将首页设为一个反馈位置，最多显示最近完成活动的一条，不生成待处理队列。

[三种状态对照](https://www.figma.com/design/I0Q7mK9wBhOqcuruuklkIf?node-id=141-586) · [可点击流程](https://www.figma.com/proto/I0Q7mK9wBhOqcuruuklkIf?node-id=43-433&starting-point-node-id=43%3A433) · [反馈消失后的首页](https://www.figma.com/design/I0Q7mK9wBhOqcuruuklkIf?node-id=126-681)

| 触发 | 说明数据 | 首页反馈 |
| --- | --- | --- |
| 停留首页，无操作 | 不变 | 保留当前一条，不倒计时关闭 |
| 保存 | 写入刚结束活动的说明 | 输入框和整条反馈一起消失，不另留“已保存”卡片 |
| 取消修改 / 关闭反馈 | 保留原说明，丢弃草稿 | 整条反馈消失 |
| 直接开始新任务 | 保留原说明，丢弃未保存草稿 | 旧反馈退出，进入计时；不带入专注界面 |
| 新任务再次结束 | 记录本次任务，旧活动说明维持原值 | 回到新推荐首页，原位置只显示最新完成活动的反馈 |

例如：读书结束后推荐画画，反馈为“读书 · 8 分钟”。用户不填说明便开始画画，读书反馈退出。画画结束后推荐 Vibe Coding，反馈只显示“画画 · 15 分钟”。首页不会出现两条反馈，也没有待补说明数量或提醒徽标。

布局沿用当前推荐卡，反馈位置固定在卡片下方；保存或取消后自动布局收回空位，“自己选”上移，新推荐卡和开始按钮不移动。既有单条反馈 480×56、展开编辑 480×98，不因完成次数增长。活动说明仍可在原活动管理入口修改，首页不承担历史待办积压。

原型以读书、画画、Vibe Coding 三项构成连续示例；每项说明分别保存，新反馈关联最新活动。清空只影响草稿，保存按活动归属写入；不再固定写入读书。六个结束入口均复用该转换。保存、取消、关闭和开始下一项都会清理反馈显隐状态。

已验证连续两次及第三次完成、各活动独立保存、清空不改原文、保存和取消整块消失、首页至多一条及无超时关闭等 25 项原生动作/布局检查；已查看对照图和无反馈首页截图。可编辑对照图由 46 个容器、36 个文本、39 个向量及 23 个组件实例构成，不含整页截图填充。

原型仍为预设示例，不运行真实计时或持久化，不模拟任意输入。本轮未做浏览器实点或参与者测试，未修改应用代码。节点、变量、转换和检查见 [v13-page-states.json](v13-page-states.json) 的 `feedbackLifecycle`；本文件覆盖早期保存后“已保存”反馈及取消回到待编辑提示的设计。
