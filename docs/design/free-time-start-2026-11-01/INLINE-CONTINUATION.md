# 首页续做说明与清空原文

**当前反馈生命周期：** 保存、取消或开始新任务后整条反馈消失；停留首页未操作时保留。再次完成任务只显示最新一条，不叠加。见 [连续完成与反馈消失](FEEDBACK-LIFECYCLE.md)。

2026-11-02。根据用户要求，任务结束后必须立即回到可开始下一项任务的首页；更新刚完成活动的说明无需再去活动列表寻找。随后用户补充：输入框需要清空原文的选项，便于重新输入。本修订覆盖先前“完成提示铅笔跳到 STEP 编辑页”的方案。

| 状态/操作 | 页面变化 |
| --- | --- |
| 结束任务 | 直接显示新的推荐卡；示例为结束读书后推荐画画，开始按钮始终可用 |
| 记下一步 | 在推荐卡下的“读书 · 8 分钟”反馈中展开单行输入，预填读书已保存的说明；不替换新推荐卡，不跳转活动管理页 |
| 清空原文 | 点击输入框右侧橡皮擦图标；悬停提示“清空原文”。只清空当前草稿，空框显示“下次从哪里继续？”；产品实现应保持输入焦点 |
| 输入新说明 | 示例为“下次从第 48 页开始。”；填写后可点击勾号保存，悬停提示“保存说明” |
| 保存 | 更新刚结束活动的说明，输入框和整条反馈同时消失。新推荐及其下一步保持不变 |
| 取消修改 | 输入框外叉号关闭整条反馈，保留原说明；悬停提示“取消修改”。清空后取消同样保留原说明 |
| 直接开始下一项 | 所有编辑状态均允许直接开始新推荐任务；未保存的草稿不写入活动说明，旧反馈退出。下次完成时原位置只显示最新活动的一条反馈 |

“清空”是可选操作，打开输入时不会自动删除原文，也不增加确认弹窗。空草稿时保存图标弱化并无点击动作，鼓励清空后重新填写。保存值与草稿值分别使用变量，清空与取消不能覆盖保存值。

复用当前图标按钮、提示组件、字体和颜色变量；增加一个可复用输入组件及橡皮擦 SVG 图标。三个编辑状态使用同一输入组件，输入区 350×44，保存和取消均为 44×44；整个编辑反馈为 480×98，与新推荐卡同屏。原主流程与批注总览中的完成反馈副本已同步。六个计时结束入口已改为返回这版首页。

已核对清空和重新填写状态的完整截图；后续已用 25 项原生动作/布局检查核验保存和取消整块消失、清空不覆盖原文、新推荐不变和连续完成不叠加。Figma 用预设示例模拟填写，不能任意键入，也没有实际 DOM 输入焦点或真实数据持久化；这些属于后续实现验收。未进行浏览器实点或参与者测试。本次只改产品与设计交付，未改应用代码。
