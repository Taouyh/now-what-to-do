# 原型测试方案

状态：未招募、未执行、没有结果。本文件提供后续主持式纸面或可点击原型测试任务，不授权联系他人或采集个人数据。范围见 [方向草案](README.md)，界面见 [线框](PROTOTYPE.md)。

## 比较什么

先验证快速启动，再验证收尾与接续带来的增量；小样本避免一次比较太多变体。

1. 第一轮：用户平时的做法 / 自己活动的普通随机清单 / 情境过滤＋具体第一步。使用匹配的活动和空档，轮换顺序，不让同一任务的熟悉程度决定结果。
2. 第二轮：在上述简化方案上，比较“加入停止点、可选接续记录”的完整方案，特别观察第二次空档。第一轮若仍有明显启动阻碍，先修正它。

目标为 8–12 位贴近场景的人，至少 8 位完成有效对照；包括无活动库者、短空档者、愿意休息者。现有研究没有证明该样本代表市场。

## 给参与者的任务

| 任务 | 中性提示 | 重点观察 |
| --- | --- | --- |
| 首次无活动库 | “你有 10 分钟空闲，还没在这里保存过内容。像平时一样决定接下来做什么。” | 能否无需建库开始；是否被提问拖慢 |
| 自己的活动 | “你有 15 分钟，身边有一本读到一半的书。决定怎么用这段时间。” | 是否理解第一步；真实翻书所需时间 |
| 条件不符 | “你现在不能出声，也没有画具。处理这个不合适的建议。” | 能否拒绝、换选；是否重复推荐不可行活动 |
| 空档缩短 | “你刚得知只剩 5 分钟，准备还没完成。按你的意愿继续。” | 能否缩短或退出；估时是否包含准备和收尾 |
| 中断与收尾 | “你需要临时停下。如果以后还想做，按自己的习惯处理。” | 是否自发留位置；留记录的时间与负担 |
| 回访接续 | 下一次实际出现空档时观察，任务测试可用“你又有一段空闲，请自行决定。” | 记录是否可用、能否更快接续；主持要求的打开不算主动复用 |
| 无结果 / 休息 | “当前建议都不合适。按你的意愿结束这次选择。” | 能否休息或退出；是否有负罪感或被迫继续 |

测试时不提示用户“应该保存”或“应该复用”。结束后追问：“刚才哪里让你停下来？”“下次有空，你会先用什么办法？为什么？”主观意愿不能替代实际再次使用。

## 怎样记录

每次记录：匿名参与者标识、方案、首次或回访、可用空档、是否有个人活动、已知限制、配置用时、选择用时、准备用时、真实开始或未知、跳过次数、空档内收尾情况、记录用时、负担与本人是否认可这段时间。

从入口到真实活动开始为主指标；选择确认和点击开始是代理指标。失败和未知分别报告，不能只比较成功启动的样本。选择休息单列，并检查是否符合用户本意，不记为活动启动失败。

7 天复访可由参与者自愿做简短日记：是否有相关空档、是否主动打开、是否接续、是否有外部提醒；无需访问其他应用或私人内容。通知推动和主持指令触发的打开单列。

报告同时给出：中位启动用时、60 秒内真实开始比例、未开始与未知数量、配置和记录成本、空档内妥善停止比例、至少一次无提醒主动复用的人数及分母。分母区分全体参与者与期间确有相关空档者，报告人数而非只给百分比。

## 预先约定的探索决策线

沿用研究报告的探索目标：至少 8 位完成有效对照，多数人的启动时间下降，组内配对中位改善约 30%，且一周内至少半数主动复用。比例须同时报告人数与空档机会；这些是团队决策线，不是行业基准或统计证明。

新增的停止点和接续机制仅在回访确有帮助、且没有明显增加首次配置与收尾负担时保留。先用观察定位问题，再决定是否增减功能，不为小样本制造显著性结论。

- 若选择更快但真实启动未改善，优先减少准备成本、修改第一步。
- 若大量换一件仍不行动，优先修正可行性与活动质量。
- 若接续记录常被跳过、很少再用，降低记录成本或移除该环节的核心地位。
- 若首次有新鲜感、后续无人主动复用，不能据此进入付费验证。
- 若休息是本人满意的结果，保留这条路径；不以填满所有空档作为成功。

完成后形成结果与范围决定，再依阶段指南决定是否进入第三阶段。不得把本方案中的目标值写成已达成成果。
