# 推荐反馈与可重复任务验收记录

日期：2026-10-20。HEAD 保持 `5ffbaef`，未提交。开始时已有上一轮修改：`app.js`、`README.md`、推荐测试和验证记录；本轮在其基础上修复，未丢弃、重置或暂存这些修改。

用户确认实际入口是双击本地 `index.html`。本轮测试同时覆盖独立配置中的本地文件及 HTTP 入口，没有读取日常浏览器的 localStorage。

## 定位与复现边界

### 1. 条件变化后旧推荐

进入本轮时，上一轮未提交代码已经在偏好保存成功后调用 `random()`，失效推荐清除和开始前复核的隔离测试通过；没有复现“无候选仍保留旧卡片”的现象，因此不能断言用户原页面运行了哪个资源版本。原页面资源标识仍为 `20261017-click-fix`，这也不足以单独证明缓存就是原因。

本轮补足新要求：条件变化只复核并保留仍有效的卡片，必要时重新选择，无候选时明确显示“没有符合当前条件的任务”，且没有开始按钮。旧按钮即使被持有，也不能启动已失效推荐。时间、环境、电脑条件的修改不改变活动计时存储。

### 2. 推荐/换一个看似无响应

确认两个按钮有事件处理器，当前动态 DOM 的重新创建会重新绑定事件，未发现 HTML 安全修复导致的监听丢失。

复现了选择结果不变：旧算法可能再次随机抽中上一项；或硬条件候选虽有多个，但近 7 天避重后只剩一个，两个按钮始终显示同一任务且没有说明。这是可见结果问题，不能据此声称事件根本没有执行。

新规则在主动点击时，若硬条件候选至少两个，先排除上一项，再在其余候选内使用近期避重偏好。只有一个候选时保留它，并显示“当前条件下只有这一项符合要求的任务”。无候选时使用空状态。按钮通过函数事件重新执行推荐，不写入历史或修改任务。

### 3. “已完成”来源及新语义

旧 `goals()` 对每个目标的任务执行 `d.completed.some(c => c.taskId === t.id)`，得到“历史上至少完成过一次的任务数”，再计算永久进度。旧 `tasks()` 的 `fd` 复选框使用相同历史判断。两者都不区分今天或过去，也不依赖任务自身的永久完成布尔值；这与“可重复学习活动”的产品语义冲突。

隔离历史数据可复现目标页出现 `1/2`、`1/1` 等永久完成数量。并不需要今天新增记录，也不能据此认定应用伪造了今天的完成记录。

原 `today()` 已通过 `new Date(...).toDateString()` 按浏览器本地日期过滤，而非截取 UTC 日期字符串。默认主数据的 `completed` 为空；迁移只保留记录并补缺失 ID，推荐、初始化、计时恢复及自动追加均不调用完成记录新增。产品代码中新增完成记录的入口仍只有 `finishTimer()`，有完成 ID 防重复处理。

未读取真实数据，不能逐条判断用户现有记录属于真实执行、日期解释异常、历史导入、重复写入或其他来源。本轮测试没有复现初始化、恢复或自动追加凭空生成记录。

## 实施前报告的最小方案及兼容性

先向用户报告了方案，再实施：

1. 只修改推荐条件复核和主动换推荐的选择顺序，保留全部时间、环境、电脑、启用及目标有效性硬限制。
2. 移除任务库“已完成”复选框、对应筛选谓词和监听；不删除任何存储字段，不把历史状态重置为 false。
3. 目标页移除永久完成数量和比例进度条，改为可重复任务数量与今日投入时长。
4. 新建 `recordsForLocalDay()`，供今天页和目标页共用本地日期口径。今天页展示及汇总口径没有改成 UTC，也没有对记录去重或删除。
5. 目标归属已有历史 ID 时优先使用；缺失时仅根据现存任务关联。这是视图上的兼容回退，不能恢复缺失的历史目标归属，不能归属的记录仍完整保留在今天页/备份中。

仍是原有 v2 数据和两个存储键，无格式迁移。`finishTimer()`、`restoreTimer()`、存储保护、数据迁移和历史写入代码未改。旧记录不补造开始/结束时间。旧任务额外的 `completed`、`done` 等字段不删除、不重置，本轮界面不读取它们作为永久完成状态。

`index.html` 更新脚本/样式资源标识为 `20261020-repeatable-tasks`，有助于重新加载本轮资源；这不是对用户此前缓存状态的诊断。静态页面仅移除 `fd` 控件，未引入分页等功能。

## 仍需用户只读证据及验收

当前测试不能证明真实记录的来源或用户此前页面加载的代码版本。若仍怀疑“今天”页存在异常，所需最小只读证据是：

- 异常出现时的本地日期、时区和地址栏本地文件路径。
- 哪些具体记录显示在今天页，而不是仅出现于旧目标进度。
- 对应记录的脱敏 `taskId`、`recordId`/`completionId`、`completedAt`、`date`、已有的 `startedAt`/`endedAt` 与有效时长字段。任务名称、反思等私人内容不需要提供。

这些字段可用于区分本地日期、相同会话 ID 重复、同任务不同会话的正常反复执行，以及缺失时间的旧记录；单凭记录仍不能证明用户现实中是否真正执行了任务。未经明确同意，不会清理或修复真实历史数据。

尚未执行用户日常浏览器配置验收、多浏览器、移动端、人工视觉或真实系统休眠测试。缺少目标 ID 的历史归属只提供上述视图回退；多标签页存储一致性等既有独立风险未处理。重新加载本地 `index.html` 后由用户实际验收；本轮不提交、不推送、不部署，也不继续分页。
