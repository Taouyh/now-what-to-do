# 空白初始化与长期活动兼容验证

日期：2026-10-20。基线提交：`739715fe07d3110dc854c8dfe8ca4271eefb3141`，分支 `master`。开始时存在推荐反馈及可重复任务相关未提交修改，已保留并按本轮新要求继续调整；没有提交、推送、部署或操作真实浏览器数据。未发现适用的 AGENTS.md。

## 实际问题与处理

- `freshData()` 原本创建 3 个任务和 3 个目标。`migrateData()` 还调用 `seedDefaultTasks()`，当旧数据缺少或关闭 `defaultTasksSeeded` 标记时补入默认内容；导入共用该路径。因此单纯清空初始化数组无法修复导入及旧空库恢复默认的问题。现在移除两条补入路径及未使用的示例常量，首次只保存空数组和偏好。名称示例仅保留在 placeholder 中。
- 原任务表单要求有效目标，推荐 `ok()` 也检查目标存在。现在移除目标导航、页面、管理操作、筛选及任务表单关联项；旧 `#goals` 路径回到开始页。仅取消目标对任务使用的约束，时间、环境、电脑、启用状态及既有近期推荐偏好保持不变。没有新增分类管理或分类约束。
- 空库在开始页和任务库均提供添加引导；有任务但不匹配时显示无匹配提示并清除旧推荐。删除操作成功后同步校验推荐，旧的开始按钮不能执行已删除任务。
- 完成结束的是一次执行。活动继续保留，今天页按本地日期显示“次执行”；永久完成筛选不再显示。暂停、继续、提前完成、放弃、自动追加、记录防重复及 JSON 备份能力继续保留。没有新增日记、分页或统计模块。

## 数据兼容与恢复

存储仍使用 `whatToDoData` 和单独的 `activeTimer`，主数据格式继续为 v2。没有更换存储键、清空存储或批量删除已有任务。旧 `goals`、`goalId`、目标名称快照、可选分类、旧默认标记和其他扩展字段继续保存在数据与 JSON 备份中。编辑旧任务使用原对象字段合并，只更新表单中的活动属性。

合法备份可以不含 `goals`，兼容时仅在内存中补为空数组；有旧目标时继续校验其结构并完整保留。任务可以没有目标或指向已不存在的目标，均不影响编辑、推荐和执行。目标对象不会被转换为活动。

已有数据的迁移只在内存中执行，不因启动或升级自动回写，重复执行不创建默认内容或重复记录。原有缺失记录 ID 的兼容仍保留，不伪造开始或结束时间。本轮没有新增需要自动改写存储的迁移，因此没有另设自动备份键；建议用户在主动修改或导入前使用 JSON 导出。异常保护仍可导出原始内容。导入仍是经校验和确认的整份替换，失败按现有事务回退；单独的活动计时不参与主数据导入导出。

旧示例和用户自建活动可能同名，不能可靠区分。安全清理方法为先导出备份、取消任务库筛选、逐项核对删除并确认。删除任务保留历史记录和旧目标数据。没有实现批量清理，也没有按名称或默认 ID 自动删除。恢复备份属于整份替换，应先再次导出当前数据。

## 不同入口与缓存

仓库没有 Service Worker 注册、Service Worker 脚本或 Cache API 使用。HTML 使用脚本与样式版本参数；本轮更新资源版本以重新获取代码，不清理浏览器数据。

`localStorage` 依据 origin（协议、主机、端口）隔离，同 origin 的不同路径一般共享；浏览器配置不同也会有不同数据。`file://` 的存储行为由浏览器决定，不能假定跨文件共享。本轮在同一隔离 Chrome 上下文中依次访问本地文件与本地 HTTP，各保存不同任务，切回后分别恢复，验证入口间不会自动同步。

因此入口差异和旧版自动补入路径都可能解释内容不同，但没有读取用户实际网址、浏览器配置或存储，不能判定每次现象的具体来源。缓存只影响加载的代码版本，清空浏览器数据会造成数据损失，不能作为迁移方案。切换入口前在旧入口导出 JSON，结束活动计时后再在新入口导入。旧版本代码仍可能重新补入默认内容，不应继续使用旧版保存空库。
